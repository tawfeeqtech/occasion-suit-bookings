# Intent: إضافة قطع المخزون عبر API مخصص لـ n8n

## Status: approved

## Author: tawfeeq

## Date: 2026-10-11

---

## What problem does this solve?

يريد أصحاب المحلات والموظفون تسجيل قطع المخزون الجديدة بسهولة وسرعة دون الحاجة لملء نماذج طويلة ومعقدة في لوحة التحكم يدوياً في كل مرة.
حالياً، توجد عقدة جاهزة في n8n تحتوي على بيانات القطعة المستخرجة من رسائل الموظفين/المالك (سواء كانت تسجيلاً صوتياً أو نصاً عادياً)، ويتم توثيق هذه القطع في ملف إكسل.
المشكلة الحالية هي عدم وجود نقطة اتصال برمجية (API Endpoint) في مشروع لارافيل تتيح لـ n8n إضافة وتخزين هذه القطع تلقائياً وفورياً داخل قاعدة بيانات المحل المعني.

## Who is affected?

- **مالك المحل (Shop Owner):** يستطيع إضافة قطع جديدة للمخزون بسهولة ومتابعة ما يتم إضافته.
- **موظف المحل (Staff):** يستطيع إضافة قطع جديدة مباشرة وبأقل مجهود وبحقول مرنة عند وصول بضاعة جديدة.
- **عقد وأتمتة n8n:** تستدعي الـ API لربط إضافة القطعة بين ملف الإكسل ومشروع لارافيل.

## What should happen?

- توفير نقطة نهاية برمجية معيارية `POST /api/v1/items` في لارافيل.
- المصادقة وتحديد المحل تتم عبر ترويسة `X-Telegram-User-Id` (مع دعم قراءة `telegram_user_id` في الطلب) للتحقق من هوية الموظف أو المالك المصرح له، وتعيين سياق المستأجر (`tenant_id`) تلقائياً، مع إمكانية التحقق الإضافي من معرف المحل إذا أُرسل.
- قبول إضافة قطعة واحدة في الطلب مع الحقول المطلوبة والمرنة.
- الحقل الإلزامي الوحيد هو اسم القطعة (`name`).
- جميع الحقول الأخرى اختيارية لمنع تعطل المستخدم إذا لم يتذكر كافة التفاصيل:
  - التصنيف (`category`): اختياري، ويدعم النصوص العربية المرنة (مثل: بدلة، قميص، حذاء...)، وفي حال عدم إرساله يُعيّن افتراضياً "عام".
  - المقاس (`size`): اختياري، ويُعيّن افتراضياً "غير محدد" في حال عدم إرساله.
  - اللون (`color`): اختياري، ويُعيّن افتراضياً "غير محدد" في حال عدم إرساله.
  - سعر الإيجار (`rental_price`): اختياري، ويُعيّن افتراضياً `0.00` إذا لم يُحدد.
  - الحالة (`status`): تُعيّن دائماً وافتراضياً على `available` (متاح).
  - حقول مخصصة (`custom_fields`): كائن JSON اختياري لحفظ أي تفاصيل إضافية (مثل `item_code` أو ملاحظات خاصة بملف الإكسل).
- عند النجاح، يعيد الـ API كود الحالة `201 Created` مع كائن JSON كامل لبيانات القطعة عبر `ItemResource`، ليتمكن n8n من استخدام المعرف والبيانات وتأكيد العملية.
- تسجيل سجل تدقيق (Audit Log) في النظام يوثق قيام المستخدم (الموظف/المالك) بإضافة القطعة عبر الـ API.

## What should NOT happen?

- يجب ألا يُسمح بإضافة أي قطعة لمستخدم غير مسجل في القائمة البيضاء لتيليجرام أو تم إلغاء تفعيل حسابه (إرجاع `401 Unauthorized` أو `403 Forbidden`).
- يجب ألا يُسمح بإضافة قطعة خارج نطاق المستأجر الخاص بالمستخدم المصادق عليه (عدم اختراق عزل المستأجرين Tenant Isolation).
- يجب ألا تفشل الإضافة إذا لم يُدخل الموظف المقاس أو اللون أو التصنيف أو السعر؛ يجب اعتماد القيم الافتراضية بسلاسة.
- يجب ألا يتم تعديل أو استبدال ملفات الإكسل من داخل لارافيل؛ مسؤولية ملف الإكسل تقع بالكامل على سير عمل n8n الخارجي.

## How will we know it works?

- إرسال طلب `POST /api/v1/items` مع ترويسة `X-Telegram-User-Id` صالحة وحقل `name` فقط، ينجح في حفظ القطعة بالقيم الافتراضية ويعيد `201 Created`.
- إرسال طلب بجميع الحقول العربية والمخصصة يحفظ كافة البيانات بشكل صحيح.
- محاولة الإرسال بدون `name` تعيد كود خطأ التحقق المعياري `422 Unprocessable Content`.
- محاولة الإرسال بترويسة تيليجرام غير مصرح بها تعيد كود `401 Unauthorized`.
- التحقق من إنشاء سجل في جدول `audit_logs` يرتبط بالقطعة المضافة والمستخدم الذي أضافها.

## Notes

- يعتمد المشروع على PostgreSQL و `stancl/tenancy` مع حقول `tenant_id` المعزولة على مستوى قاعدة البيانات.
- يتم ربط الأتمتة الخارجية في n8n مع الـ API الداخلي للارافيل على نفس الخادم المحلي (VPS).
